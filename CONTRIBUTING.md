# Contributing

Thanks for wanting to help! The game lives or dies by its *feel*, so a few rules:

1. **Feel before features.** Tune with the live panel (<kbd>~</kbd>), then copy the values into `src/tuning.ts`. If a change moves a target in `docs/FEEL.md`, update the doc and the matching test in `tests/unit/feel.test.ts` on purpose.
2. **Keep `src/sim/` pure.** No rendering in there: it is unit-tested in Node and must stay deterministic for a given seed and input.
3. **Before opening a PR**, run:
   ```bash
   npm run lint && npm run typecheck && npm test && npm run build && npm run test:e2e
   ```
4. **Commits** follow [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `perf:`, `docs:`…), one logical change each.
5. **Original assets only.** Everything is generated by code: no ripped models, sounds or names from other games.
