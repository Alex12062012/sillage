# Les 5 plus gros risques et leurs parades

| # | Risque | Prob. | Impact | Parade | Signal d'alerte / test |
|---|---|---|---|---|---|
| 1 | **Perf mobile** : terrain dense, centaines de sapins, particules, pixels haute densité → FPS < 30 sur un téléphone moyen | Haute | Critique | Matériaux Lambert sans texture ; instancing par chunk ; grille de terrain cisaillée (pas de triangles hors couloir) + LOD à 2 niveaux ; pools de particules, zéro allocation par frame ; pixel ratio plafonné par niveau de qualité + **baisse adaptative** si la frame dépasse 22 ms ; brouillard qui borne la distance de vue ; ombre blob au lieu de shadow maps | Mesure Playwright avec CPU ×4 à chaque phase ; `renderer.info` (draw calls / triangles) affiché dans le panneau debug |
| 2 | **Terrain** : coutures entre chunks, fissures de LOD, skieur qui flotte ou s'enfonce, tremplins qui ne font pas décoller ou font décoller partout, sortie de piste dans le vide | Moyenne | Haute | Même fonction de hauteur pour la physique et le maillage (rendu = échantillonnage) ; skirts ; profil en bol + talus + mur invisible à ±150 m ; seuil de décollage réglable ; génération déterministe testée (continuité, normales) | Tests Vitest de continuité ; captures au ras du sol ; bot qui descend les 3 pistes sans chute |
| 3 | **Caméra / motion sickness** : FOV qui pompe, roulis, shake, caméra 1re personne qui tangue | Moyenne | Haute | Caméra de poursuite basse **par défaut** (pas la 1re personne) ; caméra qui suit la vitesse et non les skis (stable en vrille) ; roulis ≤ 4° ; shake réservé aux impacts ; FOV lissé (τ ≈ 0,3 s) ; **mode confort** : FOV fixe, sans shake ni roulis, slow-mo réduit | Captures à 20/60/100 km/h ; revue des valeurs extrêmes dans `FEEL.md` |
| 4 | **Contrôles tactiles** imprécis ou non découvrables (pouces qui cachent l'écran, gestes en conflit) | Haute | Haute | Schéma simple : maintenir gauche/droite = carver (rampe analogique 0,2 s), deux pouces = tuck, glisser haut = saut, glisser bas = frein ; aide contextuelle de 4 s ; option gyroscope ; mode gaucher ; zones larges ; `touch-action: none` | Playwright avec émulation tactile (iPhone / Pixel) : une run complète pilotée au toucher ; vérification des zones |
| 5 | **Scope** : 7 phases, un jeu complet, déploiement, tout en une session | Haute | Critique | Portes de phase strictes (*feel before features*) ; une seule piste jouable tant que la Phase 2 n'est pas validée ; contenu procédural plutôt que fait main ; pas de backend, pas de musique composée, pas de boutique ; v2 notée dans `ROADMAP.md` au lieu d'être construite | Commit et bilan à chaque phase ; tout ce qui dépasse est noté « v2 » et non implémenté |

**Risque bonus (organisation) :** une autre session Claude construit en parallèle un projet similaire dans `~/firnline`. **Parade :** dossier, nom, repo et port de dev distincts (`~/sillage`, port 5180). On ne touche jamais aux fichiers de l'autre session.
